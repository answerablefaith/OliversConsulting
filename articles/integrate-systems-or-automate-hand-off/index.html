Should you integrate your systems or automate the hand-off?

System integration and workflow automation solve different problems. The right choice depends on frequency, data stability, failure cost and how much human judgement the process needs.

Published 24 July 2026Updated 26 July 2026By Henry OliverUK SME operations
Quick answer

Choose full system integration for frequent, stable and time-sensitive data flows. Choose controlled workflow automation when existing exports, files or APIs already contain the right data but repeated checking and movement remain manual. Keep a process manual when volume is low, judgement dominates or the business rules are still changing.

When two systems do not talk to each other, the first instinct is often to build an integration. That can be right. It can also be an expensive answer to a process that has not yet been understood.

The useful question is not simply whether the systems can connect. Ask what must move, how often it moves, which checks are required and what should happen when the data is wrong.

My view is that many SMEs buy too much architecture too early. They pay for a permanent connection before proving that the hand-off itself is stable. A lighter workflow often reveals the real rules faster and at lower risk.

My rule: integrate stable systems when the flow is frequent and predictable. Automate the hand-off when the systems can stay as they are but repeated data movement should not remain manual.

When does full system integration make sense?

A full integration suits a process that runs often, uses settled rules and needs data to move quickly. Examples include frequent order status updates, stock movements or customer records that must remain aligned throughout the day.

The connection still needs controls. Define the source of truth, field mapping, authentication, retry rules, duplicate handling, monitoring and an audit trail. GOV.UK’s API technical and data standards make the same broad point: APIs should be designed, built and operated consistently, rather than treated as a one-off cable between systems.

A technical connection can move bad data perfectly. That is why stock sync between Shopify, Amazon and eBay fails when ownership, buffers and bundle rules are unclear.

I expect more software vendors to improve their APIs, but that will not remove this problem. Easier connections will make weak business rules more visible because companies will be able to move mistakes faster and across more tools.

When should you automate the hand-off instead?

Many SME processes do not need a permanent live connection. They need a repeatable way to collect, parse, check, transform and move data between existing systems.

For example, a team may export invoices, add customer references, check totals and upload the result into finance software. A controlled automation can parse the export, use a lookup table for references, run a tolerance check on totals and create a review-ready file. The finance system does not need to change.

This is often faster to test because it follows the real operating rhythm. Bad rows can stop in an exception queue instead of entering the next system silently. The same principle removes repeated typing when wholesale orders are entered into Sage or Xero.

My preference is to prove the hand-off before making it invisible. Once a workflow has run cleanly for several cycles, the business has evidence for a deeper integration. Before that point, visibility is an advantage, not a weakness.

What should a controlled hand-off include?

A useful controlled workflow does more than copy a file from one folder to another. It should collect the source, validate the structure, apply mappings, check totals, identify duplicates and show failed records in an exception queue.

For a supplier update, that might mean reading a price file, mapping supplier SKUs to internal products, stopping prices below an agreed margin and passing approved rows into the next system. The wider process is explained in the guide to automating supplier price lists across Shopify, Amazon and wholesale channels.

I think this middle layer is undervalued. It gives the business a place to make rules explicit without forcing every rule into either system. In practice, that can reduce both technical complexity and operational dependence on one person.

When is a manual process still the right answer?

Do not automate a task only because it is annoying. If it happens twice a month, takes ten minutes and depends on commercial judgement, a clear checklist may be the better investment.

Manual work becomes a stronger automation candidate when it is frequent, rules-based, error-prone or difficult to recover. Low-volume judgement work is different. The cost of building and maintaining automation can exceed the capacity it releases.

This is also a data question. The ICO’s data minimisation guidance says personal data should be adequate, relevant and limited to what is necessary. A new integration should not copy every available field simply because it can.

I think the next wave of useful business automation will be less about connecting everything and more about deciding what should not move. Selective hand-offs, clear review points and smaller data footprints will often be safer than one large connected estate.

How should you compare the commercial options?

  1. Map the hand-off. Name the source, destination, fields, frequency, owner and current failure points.
  2. Separate transfer from judgement. Identify which parts move data and which parts need a person to decide.
  3. Choose the lightest safe option. Start with a checklist, controlled automation or full integration based on the matrix.
  4. Define proof. Measure cycle time, rework, failed transfers, manual touches and recovery effort before and after.

Suppose a team spends six hours each week exporting, cleaning and re-entering data between two systems. At a loaded cost of £30 an hour, the task costs £180 a week. If a controlled automation removes four and a half hours, it releases £135 of weekly capacity. A £3,000 build has a simple time-only payback of about 23 working weeks.

Use your own numbers and include maintenance. The automation ROI framework explains how to test payback without pretending every saved hour becomes cash.

My preference is to make the business case survive conservative assumptions. If the project only pays back when every transaction succeeds and maintenance costs nothing, the decision is being driven by optimism rather than evidence.

How should you pilot the chosen option?

Run the proposed solution beside the current process for several complete cycles. Include a failed file, duplicate record, missing field and a case that needs human judgement. Measure pass rate, exception volume, review time and recovery effort.

Do not judge the pilot only by speed. A faster process that creates invisible errors is worse than the manual process it replaced. The pilot should prove that valid records move faster, failed records stop safely and someone can explain every outcome.

My prediction is that mature SMEs will increasingly treat controlled automation as a proving ground for integration. The workflow will become the place where rules are tested, ownership is clarified and evidence is gathered before a permanent connection is commissioned.

What should you do next?

Pick one repeated hand-off and document what enters, what leaves and every decision in between. Then run the lightest safe version first.

That may be a better checklist, a controlled workflow or a full integration. The goal is not the most technical answer. It is the smallest reliable solution that removes repeated work, protects the data and keeps unusual decisions visible. This is the same process-first test to apply before adding ecommerce admin headcount.

FAQs

What is the difference between system integration and workflow automation?

A system integration creates a direct connection between applications. Workflow automation can use exports, files, emails or scheduled API calls to move and check data without permanently joining every system.

When is a full API integration worth it?

A full API integration is usually worth considering when the process is frequent, the source fields and rules are stable, failures are costly and near-live updates matter.

When should a business keep the process manual?

Keep the process manual when volume is low, decisions vary case by case or the rules are not settled. Improve the checklist and ownership before paying to automate uncertainty.

How should an SME compare integration costs?

Compare build cost, maintenance, licence fees, monitoring, recovery effort and the value of time released. Use measured current workload rather than assumed savings.
