Mortgage broker workflow guide

How mortgage brokers can automate document collection without weakening the advice file

Automate the chasing and organisation. Keep the meaning of the evidence, suitability and advice with the person responsible for the case.

Published 20 August 2026Updated 20 August 2026By Henry OliverMortgage broker operations
Quick answer

Mortgage brokers can automate document collection by giving every case a required-evidence list, sending requests and reminders from that list, linking each received file to the right customer and evidence type, and routing incomplete or conflicting items to review. The workflow should never treat “file received” as the same thing as “advice supported”.

Key takeaways:

  • Use one case-level evidence list instead of chasing from memory and inbox searches.
  • Automate technical checks such as missing files, unreadable uploads and stale requests.
  • Keep suitability, affordability interpretation and advice conclusions outside the automation.

This is operational guidance, not mortgage, compliance or legal advice. Firms should apply their own compliance framework and current FCA requirements.

A mortgage case can create a surprising amount of admin before an adviser reaches the judgement-heavy work. Payslips arrive in one email. A bank statement comes through a portal. Identification is attached to a reply. A second applicant sends a different version later. Someone updates the CRM, someone else renames the files, and the adviser still has to work out what is missing.

That is a strong automation problem because most of the movement is repetitive. The dangerous mistake is to automate the conclusion as well as the movement.

My view: a mortgage workflow should make the evidence easier to find and the gaps harder to miss. It should not make the advice decision less explainable.

Why is the advice file the control boundary?

The FCA's Mortgage Conduct of Business rules require firms giving regulated mortgage advice to keep customer information and a record explaining why the advice is suitable. The current MCOB 4 advising and selling standards also require relevant advised-sales records to be retained for at least three years.

The FCA's MCOB record-keeping schedule gives a wider view of the records firms may need across mortgage activities. The exact requirement depends on the activity and customer journey, so a workflow should not hard-code one universal “complete file” definition for every case.

That gives a useful design rule: automate evidence logistics around the case, but keep the regulated meaning of that evidence visible to the person accountable for the advice or decision.

Use five evidence states, not one “received” tick

A binary received/not-received field is too weak. I would use five states so the team can see what the automation has actually established.

StateWhat it meansAutomation action
RequestedThe customer has been asked for a defined itemSend the request, timestamp it and set the next reminder
ReceivedA file or answer has arrivedLink it to the correct case and evidence category
IncompleteThe item fails a clear technical or completeness ruleExplain the gap and request the missing part
Ready for reviewThe file is present, readable and associated with the casePlace it in the review queue with source and date visible
ReviewedThe responsible person has considered the evidenceRecord reviewer, date and outcome without overwriting the source file

The distinction between “ready for review” and “reviewed” matters. A workflow can determine that a PDF opened correctly and contains all pages expected by a simple rule. It cannot safely infer that the document supports a suitability conclusion merely because the file exists.

What can the workflow automate safely?

Start with deterministic tasks. Create the case record once. Generate the evidence checklist from the case type and your approved operating rules. Send the first request. Record when the customer responds. Save the file to the agreed location. Apply a naming convention. Check whether a required file is still missing. Send a reminder after the approved interval. Stop reminders once the item arrives.

You can also detect obvious operational exceptions: a password-protected file the team cannot open, a blank upload, a duplicate file, a document linked to the wrong applicant, or a request that has been outstanding beyond your service standard.

If customers currently send evidence through several routes, fix that intake first. Our guide to email attachments, shared folders and structured forms explains the trade-offs.

What should stay in human review?

Keep anything that changes the meaning of the case in review. That includes deciding whether customer information is credible, whether additional evidence is needed, how conflicting information should be interpreted, whether advice is suitable and what should be recommended.

The FCA rules are designed around firms being able to evidence the basis of advice. A useful automation therefore makes the source material and reviewer action more traceable. It does not bury them behind an unexplained score.

This is also why I would avoid an AI summary becoming the official case record. A summary can help a reviewer navigate a large file, but the underlying evidence and the reviewer's own conclusion should remain accessible.

How should document chasing work?

Do not send the same generic reminder every two days. Use the evidence state and the last customer action.

  • If nothing has been received, remind the customer what is still needed.
  • If one of three items arrived, acknowledge it and ask only for the remaining two.
  • If an upload is unreadable, explain the technical problem rather than saying the document is missing.
  • If the adviser has asked for different evidence, stop the old reminder sequence immediately.

That sounds simple, but it removes a common source of poor customer experience: automated chasing that ignores what the customer has already done.

Measure the workflow by exceptions, not emails sent

The useful measures are not the number of reminders or files processed. Track how many cases reach review with all required evidence present, how many files are misclassified, how many reminders are sent after the item has already arrived, and how long genuine exceptions wait for an owner.

Worked example

If a brokerage has 80 active cases and staff spend an average of 12 minutes a week per case checking inboxes, renaming files and chasing missing items, that is 16 hours of weekly admin. If a controlled workflow removes two thirds of that preparation while leaving adviser review unchanged, roughly 10.5 hours a week move back to customer work and case judgement. Use your own volumes and timings before approving a build.

How would I pilot it?

Choose one standard case type and a small number of advisers. Map the exact evidence states, approved request wording, storage location, reminder intervals and stop conditions. Run the automation beside the current process for several cases.

Review false positives first. A missed reminder is annoying. A workflow that marks the wrong evidence as complete is more serious. Tune the rules until staff trust the case status without needing to rebuild it from the inbox.

Mortgage broker document automation FAQs

Can a mortgage broker automate document collection?

Yes. Requests, reminders, file naming, completeness checks and routing can be automated. Advice, suitability conclusions and judgement about the meaning of customer information should remain controlled by the authorised people responsible for the case.

What should the workflow track?

Track what was requested, when it was requested, what arrived, whether the file is readable and complete, which case it belongs to, who must review it and whether further evidence is required.

Should automation decide whether a document proves affordability?

No. It can identify that a document exists and passes defined technical checks. The regulatory or advisory meaning of that evidence should stay with the person responsible for the assessment.
