Mortgage broker workflow guide

How mortgage brokers can automate document collection without weakening the advice file

Automate the chasing and organisation. Keep the meaning of the evidence, suitability and advice with the person responsible for the case.

Published 20 August 2026Updated 20 August 2026By Henry OliverMortgage broker operations
Quick answer

Mortgage brokers can automate document collection by giving each case a clear evidence list, sending targeted requests and reminders, linking every received file to the right customer and evidence type, and routing incomplete or conflicting items to review. Automate the logistics around the advice file, not the judgement inside it.

A mortgage case can create a surprising amount of administration before an adviser reaches the work that actually needs judgement. Payslips arrive by email. A bank statement comes through a portal. Identification is attached to a reply. A second applicant sends a newer version later. Someone updates the CRM, someone else renames the files, and the adviser still has to work out what is missing.

That is a strong automation problem because most of the movement is repetitive. The mistake is treating the conclusion as just another thing to automate.

My view: a mortgage workflow should make evidence easier to find and gaps harder to miss. It should never make the advice decision less explainable.

What should mortgage brokers automate first?

Start with the parts of the case that can be described as simple states and rules: what was requested, what arrived, what is still missing, whether a file opens, which applicant it belongs to, and who needs to review it next.

Those are operational questions. They are different from deciding whether the evidence is credible, whether affordability has been demonstrated or whether a recommendation is suitable.

I think businesses often lose trust in automation because they start at the most impressive-looking end of the process. A summary model or decision engine gets attention. The repetitive evidence chasing underneath it remains messy. In mortgage operations, I would reverse that order. Make the file reliable first. Better judgement becomes easier when the reviewer is no longer reconstructing the case from several channels.

Why is the advice file the control boundary?

The FCA's Mortgage Conduct of Business rules on advising and selling set requirements around regulated mortgage advice and the basis on which it is given. The FCA's MCOB record-keeping schedule also sets out records firms must retain for different mortgage activities.

The practical point for automation is straightforward: a workflow can improve how evidence is collected and presented, but it should not quietly become the source of the regulated conclusion. The underlying customer information, the review action and the basis for the advice need to remain traceable.

This is operational guidance rather than mortgage, compliance or legal advice. Firms should apply their own compliance framework and current FCA requirements.

Use five evidence states, not one "received" tick

A binary received/not-received field is too weak. It tells the team a file exists, but not whether anyone can actually use it. A five-state model gives the workflow a clearer job.

StateWhat it meansAutomation action
RequestedThe customer has been asked for a defined itemSend the request, timestamp it and set the next reminder
ReceivedA file or answer has arrivedLink it to the correct case and evidence category
IncompleteThe item fails a clear technical or completeness ruleExplain the gap and request the missing part
Ready for reviewThe item is present, readable and correctly associatedPlace it in the review queue with source and date visible
ReviewedThe responsible person has considered the evidenceRecord reviewer, date and outcome without overwriting the source

The distinction between "ready for review" and "reviewed" is the important one. A workflow may establish that a PDF opens correctly and contains the pages expected by a defined rule. It cannot safely infer that the document supports a suitability conclusion simply because the file exists.

What can the workflow automate safely?

Build around deterministic steps. Create the case record once. Generate an evidence checklist from the case type and approved operating rules. Send the first request. Record the customer's response. Save the file to the agreed location. Apply a naming convention. Stop reminders when the right item arrives.

Useful checks can be simple: a blank upload, an unreadable or password-protected file, a duplicate, a document attached to the wrong applicant, or a request that has been outstanding beyond the firm's chosen service interval.

If evidence currently arrives through several routes, fix intake before adding more automation. The comparison of email attachments, shared folders and structured forms is a useful starting point. Where the issue is movement between tools rather than intake, the framework for deciding whether to integrate systems or automate the hand-off can keep the first build proportionate.

What should stay in human review?

Keep anything that changes the meaning of the case with the responsible person. That includes deciding whether information is credible, whether conflicting evidence needs investigation, whether further evidence is necessary, and what recommendation follows from the customer's circumstances.

AI can still be useful around this boundary. For example, a model may help a reviewer navigate a long document or draft a non-authoritative summary. But I would not make that summary the evidence record. The source document and the reviewer's conclusion should remain available.

My prediction is that regulated automation will become more aggressive around preparation and more conservative around final judgement. As models improve, the temptation will be to let them cross that line. The more valuable design will often be the opposite: use better AI to prepare the evidence faster while making the human decision more explicit.

How should automated document chasing work?

Do not send the same generic reminder every two days. Use the evidence state and the customer's last action.

  • If nothing has arrived, remind the customer exactly what is still needed.
  • If one of three requested items arrives, acknowledge it and ask only for the remaining two.
  • If an upload is unreadable, explain the technical problem rather than saying the document is missing.
  • If the adviser changes the evidence request, stop the old reminder sequence immediately.

This sounds basic, but it prevents a common failure mode: automation that creates more customer frustration because it ignores work the customer has already done.

How do you know whether the automation is working?

Do not judge the workflow by emails sent or files processed. Measure the exceptions it removes and the errors it avoids.

  • How many cases reach review with the expected evidence present?
  • How many files are linked to the wrong case or category?
  • How many reminders are sent after the document has already arrived?
  • How long do genuine exceptions wait for an owner?
  • How often does a reviewer have to return to the inbox to reconstruct the case?
Worked example

Suppose a brokerage has 80 active cases and staff spend an average of 12 minutes a week per case checking inboxes, renaming files and chasing missing items. That is 16 hours of weekly administration. If a controlled workflow removes two thirds of that preparation while adviser review stays unchanged, about 10.5 hours a week are released back to customer work and case judgement. This is an illustration, not a promised saving; use your own volumes and timings before approving a build.

This is also where the less obvious cost appears. Repetitive checking does not only consume minutes. It interrupts people who then have to rebuild context. The article on the interruption cost of manual admin explains why small recurring tasks can be more expensive than their stopwatch time suggests.

How would I pilot mortgage document automation?

Choose one standard case type and a small number of advisers. Do not start with the most unusual or exception-heavy cases.

1. Define the evidence states

Write down what counts as requested, received, technically incomplete, ready for review and reviewed. Decide who owns each transition.

2. Map the existing routes

List every place evidence can arrive today. Decide which route should remain authoritative and which channels should simply feed it.

3. Automate requests and technical checks first

Run the workflow beside the current process. Compare what it thinks is complete with what staff actually need.

4. Review false positives before chasing speed

A missed reminder is inconvenient. A workflow that marks the wrong evidence as complete creates false confidence. I would tune for conservative accuracy before trying to maximise straight-through processing.

5. Expand only after the operating rule is stable

Once advisers trust the case status, add further case types or deeper system connections. This is usually safer than redesigning the full advice process on day one.

When is automation probably not worth it?

If a small brokerage handles a low volume of cases, has one clear intake route and rarely chases the same evidence twice, a better checklist may solve most of the problem. Automation earns its place when the work repeats often enough, several people touch the same case, or staff spend meaningful time reconstructing evidence from different systems.

That is an important commercial test. Not every manual process deserves software. I would rather automate one repeated bottleneck with clear rules than build a broad workflow around a process the team has not agreed yet.

Mortgage broker document automation FAQs

Can a mortgage broker automate document collection?

Yes. Requests, reminders, file naming, technical completeness checks and routing can be automated. Advice, suitability conclusions and judgement about the meaning of customer information should remain with the authorised people responsible for the case.

What should the workflow track?

Track what was requested, when it was requested, what arrived, whether the file is readable and technically complete, which case it belongs to, who must review it and whether further evidence is required.

Should automation decide whether a document proves affordability?

No. It can establish that a document exists and passes defined technical checks. The regulatory or advisory meaning of that evidence should stay with the person responsible for the assessment.
