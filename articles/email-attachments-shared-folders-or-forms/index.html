Email attachments, shared folders or forms: which should your business use?

The way work enters a business decides how much checking, chasing and re-keying follows.

Published 31 July 2026By Henry OliverUK SME operations

Many automation projects start too late. The team focuses on moving data between systems, but the real damage happens when a customer, supplier or colleague first sends the information.

Quick answer

Use email attachments for low-volume, flexible work. Use shared folders when files are large, access must be controlled or retention matters. Use structured forms when the same fields are required each time and incomplete submissions create repeated checking, chasing or re-keying.

A poor intake channel creates missing fields, duplicate versions and unclear ownership. The team then spends time repairing the input before useful work can begin. That cost is often hidden because it is spread across inboxes, spreadsheets and quick messages.

My view is that the intake channel is part of the operating model, not an administrative preference. Once a business chooses how information may enter, it is also choosing which errors staff must absorb later.

What problem are you actually choosing an intake channel to solve?

The right choice depends on what arrives, how often it arrives and what happens next. A supplier price list is not the same as a customer complaint. A signed document is not the same as twelve data fields needed for a quote.

Start with four questions:

  • Does the submission need a fixed set of fields?
  • Will several people need access to the same item?
  • Does the business need a clear version and audit trail?
  • Will the data be entered into another system?

The more often the answer is yes, the weaker ordinary email becomes. Before choosing software, map the current intake in the same way you would define operating rules for a spreadsheet-heavy process: name the owner, required fields, accepted evidence and exception route.

Email attachments are flexible, but the flexibility creates work

Email works well when the volume is low and the request changes each time. People understand it. It also gives the sender room to explain unusual details.

The weakness is structure. One supplier sends an XLSX file. Another sends a PDF. A third pastes figures into the email. File names differ. Important fields are left blank. The receiver must open, interpret and often re-key the same information.

Automation can help, but the mechanism matters. A workflow may watch a mailbox, save attachments, identify the sender from the email address and apply a parsing rule or template to known file layouts. Unknown formats should go to review. The workflow should not guess where a price, date or account code belongs.

I think email is often kept because it feels convenient to the sender, while the cost is quietly transferred to the receiving team. That trade-off is acceptable for genuine exceptions. It is poor process design when the same repair happens every day.

Use email when: the volume is modest, variation is genuine, one person owns the check and a failed submission has limited cost.

Shared folders improve control, not data quality

A shared folder is useful when files are large, several people need access or the business must retain the original document. Permissions, file history and a single storage location can remove some inbox confusion.

It does not solve missing fields or inconsistent formats. A folder full of badly named files is only a tidier version of the same problem.

For a shared folder to work, define the naming rule, the owner, the accepted file types and how a new item becomes visible. A simple automation can watch for a new file, record its path and timestamp, then alert the correct person or add a row to a tracker. That is safer than asking staff to check the folder throughout the day.

Where the file itself is evidence, retention and access should be deliberate. The UK National Cyber Security Centre advises organisations to control access to information and manage permissions according to business need. That principle supports using governed folders rather than uncontrolled attachment chains when sensitive or important records are involved.

Use a shared folder when: the original file matters, access needs control, several people need the item or email size limits create friction.

Structured forms reduce repair work before it starts

A form is strongest when the same information is needed each time. Required fields, dropdown lists, date rules and simple validation can prevent incomplete records from entering the process.

The mechanism is direct. The form writes each response into a table or sends it through an API to a CRM, finance tool or workflow queue. A lookup table can convert customer names to account codes. A tolerance check can flag a value outside the expected range. The sender receives a clear error before the team has to chase them.

Forms are not always better. They can frustrate people when the request is unusual, when supporting documents vary or when the questions are longer than the work itself. A badly designed form shifts admin to the customer without reducing internal effort.

My preference is to use forms for stable facts and keep judgement outside them. Ask for the customer number, date, quantity and supporting file. Do not force a complex commercial explanation into a dropdown merely because structured data is easier to process.

Use a form when: required fields are stable, incomplete submissions are common and the answers feed another system or repeated decision.

How much can a better intake channel save?

Use a conservative calculation. Suppose a team receives 70 submissions a week. Each one takes four minutes to open, check, rename and re-key. A further 12 submissions need a six-minute chase for missing information.

That is 352 minutes a week, or just under six hours. If a form removes three minutes from each clean submission and halves the chasing, the weekly saving is about four hours. At an employment cost of £24 an hour, that is roughly £96 a week.

The decision should include build, licence and support costs. It should also include error risk. If one wrong customer code can delay an invoice or one missing quantity can hold an order, the benefit is not only time. Use the same conservative approach described in the automation ROI framework, including review time, exceptions and maintenance.

I prefer business cases that still work when some users resist the new route and a proportion of submissions remain manual. A process that only pays back at perfect adoption has not been designed for real operations.

Build one controlled intake flow

Choose one repeated submission type and document the route from sender to final system. Record the required fields, accepted formats, owner, response time and the conditions that trigger review.

Then build the smallest useful flow:

  • capture the email, file or form response;
  • record the source and submission time;
  • check required fields and file types;
  • apply known mappings and duplicate checks;
  • send unclear items to a named exception owner; and
  • write approved data to the next tracker or system.

This is similar to automating invoice intake without losing approval control. The automation should prepare clean evidence and isolate uncertainty, not hide it.

Do not automate every route at once

Start with the most repeated submission type. Map what arrives, what is checked, what is re-keyed and which exceptions need judgement.

Keep unusual work in email if that remains the clearest route. Move stable, repeated data into a form. Store original documents in a controlled folder when the record matters. A sensible process may use all three.

The aim is not to ban email. It is to stop using email as a database, a document store, a task queue and an approval system at the same time.

Where information must then move between tools, the next choice is whether to integrate the systems or automate the hand-off. That decision should follow the intake design, not precede it.

My prediction is that mature SMEs will stop treating intake as a collection of inboxes and start managing it as a controlled service. Each recurring submission type will have an agreed entry point, validation rules and a visible exception path.

Frequently asked questions

Are email attachments suitable for operational data?

Email attachments are suitable for low-volume, low-risk work when one named person checks the file and the business does not need strict version control. They become weak when several people submit files or when missing fields delay the process.

When should a business replace email with a form?

Use a form when the same fields are required each time, incomplete submissions create rework, and the answers need to enter a tracker, CRM or finance process in a consistent structure.

Is a shared folder better than email?

A shared folder is better for larger files, controlled access and clear retention. It still needs naming rules, ownership and a method for telling the team when a new item is ready.
